研究問題固定三個

RQ1：相較固定流程，能選工具補查的 Agent 是否提高關鍵主張的證據支持率？ RQ2：加入独立 Reviewer 是否更能發現並修正預先植入的矛盾、口徑錯誤與不足證據？ RQ3：在相同模型、資料與預算上限下，品質改善是否值得增加的請求、token 與等待時間？

這是小型工程與方法驗證，不預先設定雙 Agent 必須獲勝；負結果、限額失敗、無法改善都要保留。測試數不等於有效獨立財務樣本數。

三種比較模式

  • Workflow：程式固定取相同來源快照的前五筆及固定財務、總經與DCF輸入快照，單次模型撰稿，沒有動態工具選擇與覆核。這是受控基線，與原站所有功能完全等價的說法不成立。
  • Single：Researcher 可自主選工具及停止，沒有 Reviewer。
  • Dual：Researcher 加 Reviewer 與有限補查閉環。

三組同一模型 ID、版本、來源池、cutoff 與生成參數，共享「每 job 最多 8 請求、10 工具、40k token 准入」上限，不強迫 Workflow 浪費同等請求。報告實際成本與品質，說明允許工具不同是實驗變因。先看相同上限比較，再列 quality-per-call，不把較多呼叫的優勢當成免費改善。

固定 30 個案例

五類各六個：完整證據、矛盾來源、缺少關鍵資料、金融單位/期間錯誤、工具異常/不可信指令。每類 2330/2317/2454 各兩個。兩個/類作開發校準，共 10；其餘四個/類，共 20，為保留測試。

B 建立真实公司來源快照，再製作標示 synthetic_fixture=true 的變體；「故意錯誤」不能宣稱真實公司真的發生該事件。真實來源原件不可覆寫，錯誤與缺少版本分開保存。每案例固定 question、cutoff、source_ids、fixture_id、預期可支持主張、預期需拒絕主張、允許停止狀態、資料來源與授權註記。

具體案例編號與各自擾動見本章附表（由生成程式填入）。B/D 對 10 個開發案調整程式與 prompt；W06 10/23 凍結 30 案、分組、人工評分規則及 hash。20 個測試案只供 W10/11 正式評估，不利用測試答案調 prompt；若 bug 修復需重跑，發新實驗版本且保留全部舊結果。

人工評分與成本

B 與 D 分別對匿名化、打亂模式標籤的输出評分，先獨立再對差異由組長裁決；C/E 只整理表格，不負責標準答案。單純引用一個網址不算支持：需原文支持對應 claim。

第一次實驗上限：30 案 x 3 模式 x 8 = 720 次模型請求，其中開發 240、保留測試 480，實際 Workflow 通常較低。以每日6個job估計，90個job至少15個可執行日，安排 W03至W11分批；不得在期末一次才跑。實際 J 更小時由組長 W01 計算能否在 W11 前完成；不足先減少開發重跑，正式樣本數若仍需調整必須改版並說明，而非暗中删案例。

指標定義

  1. 證據支持率：被標註為 supported 的關鍵可驗證主張 / 所有關鍵可驗證主張；沒有主張回 NA，另報拒答率，不能用全部拒答取得100%。
  2. 引用可解析率：可定位到正確快照且可讀的引用 / 全部引用。與引用支持率分開。
  3. 植入錯誤檢出率：被指出的預置 critical error / 預置 critical error 總數；無錯誤案另報誤報率。
  4. 修正率：在有修正機會案例中，修正後不再出現同一 critical error 的數量 / 需要修正的數量；只有改寫措辭不算修正。
  5. 合理拒答率：不足證據案例中採 insufficient 並說明缺口的比例；完整資料案的錯誤拒答另列。
  6. 作業成功率：正常環境測試中完成有效 schema 與正確狀態的 job 比例；429、timeout、failed 全部在總表保留。可另外報排除刻意故障的分母，但不可只報漂亮子集。
  7. 成本與效能：每 job 模型發送數、usage token、工具數、active duration、queue duration、端到端時間及 RSS。列中央値、p95 和總量；每列附實際 N。無帳單不填真實美元0，寫「免費層，本次未計費；已消耗配額」。

必過工程驗收（與研究成績分開）

  • E01：三個固定示範案例在有可用配額時真的執行，工具路徑隨證據不同；至少一次覆核要求補查後修正，一次不足證據停止。Replay 僅證明回放，不能當 live。
  • E02：超過 8 次發送、10 次工具、2 輪補查均由程式阻擋；以 mock 驗證邊界並有 log。
  • E03：重複送同一任務20次只生成1個有效job；worker中斷重啟不重設預算、不重複發佈；模糊網路結果先保存未確定狀態，不聲稱 exactly-once 模型計費。
  • E04：未知工具、未授權來源ID、假引用、資料內 prompt injection、未授權建立job/發布，一律阻擋。模型無任意網路、檔案或shell工具。
  • E05：每份公開報告100%引用可解析且無未解決 critical issue；若不通過就只顯示研究不足/未發布，不勉強湊報告。
  • E06：網站與PDF來源快照、文字、數字和版本一致；桌機1440x900及手機390x844人工/自動截圖檢查；PDF至少三份，不缺中文、不切頁重疊、來源可點。
  • E07：以預熱的2GB環境測10位唯讀訪客持續5分鐘，同时1研究job；無OOM與HTTP5xx，唯讀API p95目標<2秒、RSS峰值目標<1.5GB。測試環境、網路條件與結果都記錄；未達就修/標示限制，不說2GB必然足夠。
  • E08：純讀已發佈頁/PDF0次LLM；關掉Gemini仍能讀舊報告，新研究顯示不可用而非空白；資料庫或worker故障有清楚狀態。
  • E09：建置、既有測試及新增Agent/DB測試實際通過；憑證掃描無外洩；提供rollback與備份還原演練紀錄。
  • E10：20個保留案例 x3模式完整記錄與評分；測試結果不得承諾必定達到證據支持率90%，該數字僅為改善目標，真實結果照報。

金融觀察不假裝成嚴格歷史回測

原計畫的「過去一年交給今天的 LLM 再看漲跌」容易含事後資訊與模型訓練知識，不能當無偏回測。本期採小型前瞻觀察：W07至W09每週五21:00台灣時間，三檔各凍結一份研究，共9份；截止時間與來源可得時間同存。資料不足照收錄，不補造方向。

價格評估用下一個台股交易日開盤為 entry、該日算第1個持有交易日，對第1/5/20個交易日收盤計簡單報酬；價格需同一調整口徑，若只有調整收盤、無對應開盤則標NA，不混算。無交易訊號者只展示路徑不計方向命中。停牌、缺價、未滿觀察窗標NA，不補值。11/13為最後訊號，20交易日是否成熟以實際交易日曆核對；12/11截取仍未成熟即NA。

沒有真實下單、不計實際交易成本、不做獲利承諾；這9份不是獨立大型統計樣本。報酬觀察放次要結果，核心仍為證據品質與Agent閉環。歷史案例僅稱 evidence-replay，並承認模型可能已知道後續世界資訊。
