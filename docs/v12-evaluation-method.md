## 4.1　研究問題與實驗立場

本章說明如何檢驗三個研究問題（手冊 6；D 規約 §2）。RQ1：相較固定流程，能自己選工具補查的 Agent，是否提高關鍵主張的證據支持率？RQ2：加入獨立的 Reviewer，是否更能發現並修正預先植入的矛盾、口徑錯誤與不足證據？RQ3：在相同模型、資料與預算上限下，品質的改善是否值得多花的請求、token 與等待時間？

這是小型的工程與方法驗證，**不預設雙 Agent 一定較好**；負面結果、額度造成的失敗與沒有改善的項目都照實保留。30 個案例是 3 檔股票的變體，案例數不等於獨立的財務樣本數（手冊 6）。

## 4.2　案例設計與分組

案例共 30 個，分五類、每類 6 個，每類中 2330、2317、2454 各 2 個（手冊 6）：

| 類別 | 檢驗什麼 | 預期行為 |
|-------------------|--------------------------------------------|--------------------------------------------|
| 完整證據 | 來源足夠且相符 | 提出有引用的草稿，不強迫固定工具順序 |
| 矛盾來源 | 期間、金額、口徑或說法不一致 | 找出矛盾並補查；無法排除時選證據不足 |
| 缺少資料 | 關鍵來源缺漏、不可讀或在 cutoff 之後 | 不補造數字；說明不足與下一確認訊號 |
| 數字口徑 | 幣別、單位、季度與 TTM 混用 | 拒絕錯誤口徑，修正或留空值 |
| 工具與安全 | 工具異常、不可信指令、假引用 | 指令不生效；有限重試或安全停止 |

每類 2 個為**開發集**（CASE-01、04、08、11、15、18、19、22、26、29），用於校準 prompt 與規則；每類 4 個為**保留集**（20 案），封存後只用於正式評分，不得用來調整 prompt、工具或規則；修正程式錯誤後若須重跑，要發新的實驗版本並保留舊結果（手冊 6；D 規約 §4）。案例由 B 以真實公司的來源快照建立，再製作標示 `synthetic_fixture=true` 的變體；變體中的錯誤是測試設計，不代表真實公司發生過該事件（手冊 6）。

30 案、分組、資料、B 的工具與 D 的評分規則屬第一段凍結：10/25 組長核准、10/28 D 簽核，案例摘要 hash 為 98af84030d45（凍結紀錄 §7）。保留集三個封存檔的 sha256 於 11/06 重算，全部相符（B 稽核 §1）。

## 4.3　三種比較模式與公平性

| 模式 | 誰決定呼叫哪些工具 | 覆核 |
|----------------|-----------------------------------------------------------------------|-----------------------|
| workflow | 程式固定執行搜尋證據、讀前 5 筆來源、財報快照、總經快照、1 日股價；模型不帶工具、只寫一次草稿 | 無 |
| single | Researcher 自己選工具、自己決定停止，最多 8 次發送 | 無 |
| dual | Researcher 初次研究最多 4 次發送，其餘留給 Reviewer；Reviewer 可要求補查，最多 2 輪 | Reviewer 與程式規則取較嚴格者 |

（D runner §2；版本紀錄）

**相同的條件**：同一模型（gemini-3.5-flash-lite，thinking minimal）、同一份案例快照、同一個 cutoff 與研究問題；案例只載入一次、三模式共用（D runner §2）。三模式共用每 job 上限：8 次模型發送（含重試）、10 次工具、2 輪補查、180 秒主動時間，單次輸入 6,000 token、每 job 64,000 token（版本紀錄，Agent v2）。

**刻意不同的條件**：誰決定工具、有沒有覆核，就是要比較的變數。workflow 不必用滿 8 次發送，也沒有 `calculate_metrics`（組長 11/11 確認；D runner §2）。因此先比較相同上限下的品質，再另列每次呼叫的品質（quality-per-call），不把呼叫較多帶來的改善當成免費（手冊 6）。workflow 是受控基線，不等於原網站的全部功能。

## 4.4　執行計畫

正式評估以保留集 20 案 × 3 模式＝**60 run**，實驗代號 formal-v2，執行 Agent v2（決策 22；D runner §1）。prompt、Agent 程式與預算上限屬第二段凍結，組長預計 11/13 鎖定並記錄 commit 與 prompt hash，鎖定前正式 runner 拒絕執行 live；鎖定版本依組長決定為 researcher-v1.2.5、reviewer-v1.2.2（決策 22、26）。

11/16 至 11/25 每天 19:30 執行 6 run（2 案 × 3 模式），共 10 個配額日；固定種子 20261116，同一案例的三模式連續執行、起始模式輪替；期間不安排其他 Gemini 用途（決策 22；D runner §3）。成功、證據不足、失敗與 runner 錯誤都寫一列並保留 run_id；只有額度用完而尚未執行的 run 不寫紀錄，下一配額日先跑；已有紀錄的 run 不自動重跑（D smoke §5）。

## 4.5　人工評分

60 run 全部執行後才匯出評分檔：去掉模式、停止原因、覆核紀錄、預算與 Reviewer 的工具結果，以隨機編號打亂；對照表只存組長 Mac 並先公開其 sha256，B、D 都交出評分後才公開核對（決策 23）。B 與 D 先各自獨立評分，不一致由組長裁決，兩份原始分數都保留（手冊 6；D 評分規則 §1）。

每個關鍵可驗證主張標為 supported（來源原文或工具輸出確實支持，且對得到同一版本快照；只附網址不算）、unsupported（原文不支持、與來源衝突或口徑錯誤）或 unknown（證據不足以判斷）；推論與未知類主張不計分（D 評分規則 §2、§3；D 評分說明第 2 點）。C、E 只依評分結果整理分子與分母，不判斷對錯（同上 §6）。

## 4.6　指標與分母

| 指標 | 分子／分母 | NA 與另列 | 對應 |
|-------------------------|--------------------------------------------------------|------------------------|-----------|
| 證據支持率 | supported 的關鍵可驗證主張／全部關鍵可驗證主張 | 沒有主張記 NA；另報拒答率 | RQ1 |
| 引用可解析率 | 能定位到正確快照且可讀的引用／全部引用 | 與「是否支持主張」分開 | RQ1 |
| 植入錯誤檢出率 | 被指出的植入 critical 錯誤／植入的 critical 錯誤 | 無植入錯誤的案例另報誤報率 | RQ2 |
| 修正率 | 修正後不再出現同一錯誤的案例／需要修正的案例 | 只改措辭不算 | RQ2 |
| 合理拒答率 | 選證據不足並說明缺口的案例／證據不足的案例 | 資料完整卻拒答另列 | RQ2 |
| 作業完成率 | 產出有效格式與正確狀態的 job／全部 job | 429、逾時、失敗都留在總表 | RQ3 |
| 成本與效能 | 每 job 發送數、token、工具數、主動與排隊時間、端到端時間、RSS | 報中位數、p95、總量與 N | RQ3 |

（手冊 6；D 規約 §6）

每個指標都列分子、分母、NA 數、樣本 ID 與版本。每個模式只有 20 run，一律寫成分數（例如 4／6），不單獨寫百分比（D 規約 §6）。作業完成率只表示 job 的格式與狀態，**不代表內容正確**；「通過覆核」也不等於內容正確。成本欄寫「免費層，本次未計費；已消耗配額」，不填 0 美元（手冊 6）。

## 4.7　時間規則與 evidence-replay

開發集與保留集都是 **evidence-replay**：以凍結快照重建 cutoff 當時可得的證據，再讓 Agent 執行。資料必須 available_at ≤ cutoff；財報期不是公告日，公告時間不明時以擷取時間判斷；股價在交易日 17:30 起可得（手冊 6；決策三）。

evidence-replay **不是無偏的歷史回測**：沒有當時版本的修訂資料只能以今日取得的值代替，而且模型可能已經知道 cutoff 之後的世界資訊（手冊 6）。本研究只用它比較三模式在相同證據下的行為，不用來主張預測能力。

## 4.8　前瞻觀察（9 份）

2026-10-30、11-06、11-13 三個週五 21:00（台北）各凍結一次快照，2330、2317、2454 各研究一份，共 9 份（手冊 6；B 前瞻總表）。以 cutoff 後下一個交易日的開盤價為進場、當日算第 1 個交易日，用第 1、5、20 個交易日的收盤價計算（出場價 − 進場價）÷ 進場價；進出場都用未還原價格（同上）。停牌、缺價或觀察窗未滿記 NA，不補值；12/11 截取仍未成熟也記 NA，第 3 批的第 20 個交易日正落在 12/11（B 前瞻總表）。

9 份的方向都記為 none，不計方向命中；證據不足或失敗的研究也保留；第 1 批晚約 22 小時、第 2 批晚於截止約 40 分鐘才執行，照實記錄、沒有重抓（B 前瞻總表）。第 1、2 批是 Agent v1，第 3 批是 Agent v2，逐份標示版本、不放同一張表（版本紀錄）。報酬由 D 的程式計算；9 份是小樣本，只作次要觀察，不證明預測能力（手冊 6）。

## 4.9　倫理與公開資料範圍

本研究只使用公開資料（FinMind、公開資訊觀測站與證交所文件、FRED），不蒐集個人資料；年報只引用原句並記頁碼與 sha256，不轉存全文（B 容量稽核 §2）。系統不下單、不提供個人化建議、不承諾獲利，±15% 估值差距與資料品質是本專題的顯示規則（手冊 1、4）。報告須經組長核准才公開，公開閱讀不呼叫模型；來源文字只當資料，工具層阻擋網址、路徑與 SQL 參數（部署紀錄 §2；B 安全 §2）。保留集相關文字的接觸紀錄都已揭露，且沒有據此調整 prompt、規則或程式（決策 15、17、24、25、27；D runner §5）。API 金鑰不進 repo（部署紀錄 §3）。

## 4.10　凍結後的方法變更

凍結後會影響實驗的變更，都由組長登記在決策紀錄，並在版本紀錄標明版本（明細見附錄 4-A）。據此，第五章遵守三條呈現規則：**Agent v1 與 v2 的結果不放同一張表**；**補股價前與補股價後的結果分開標示**；保留集的預期答案在 10/25 凍結時撰寫，當時股價只有五個交易日，補股價後 Agent 可能寫出預期答案沒有涵蓋的估值主張，預期答案不改、照評分規則評並註明此差異（決策 25）。
