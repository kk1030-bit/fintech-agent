6/14 專題討論手機版摘要

多智能體投資分析系統：網站深化、Render 2GB、PDF 與 Agent 定位

目前完成度

目前核心系統可說已完成約 80% 至 85%，但建議不要說「下學期已完成 8 成」。比較穩的說法是：

目前核心系統已完成 8 成以上；下學期重點是網站功能深化、Agent 流程化、PDF 網站展示、回測驗證與論文定稿。

下學期主軸

下學期不再從資料抓取或基礎網站開始，而是把網站升級成投資決策輔助平台。

  • 產業關聯圖 / 公司網絡圖
  • 同業比較與估值比較
  • Agent 分析流程狀態
  • PDF 報告網站展示
  • 回測驗證

Render 與記憶體

.io、.ai 域名不能增加記憶體，只是網址門牌。真正要解決記憶體，要升級主機或調整架構。

Render Free      512 MB
Render Starter   512 MB
Render Standard  2 GB
Starter 仍是 512MB；如果要增加 RAM，應看 Web Services 的 Standard 2GB。

下學期改成 Render 2GB

下學期計畫可改成使用 Render Standard 2GB，用來改善多股票查詢、PDF 展示、產業關聯圖與 Agent 分析流程穩定性。

下學期基礎建設將升級 Render 部署規格，
由 Free 512MB 提升至 Standard 2GB，
以改善公開網站在多股票查詢、圖表產生與 PDF 報告展示上的穩定性。

為什麼目前網站會慢

不是網站內容太多，而是每點一支股票都會觸發完整後端流程。

點股票
→ FinMind 抓資料
→ 財務分析
→ 寫入 Supabase
→ DCF 計算
→ matplotlib 產生圖表
→ 回傳前端

連點 4、5 支股票時，Render Free 會同時處理多個重任務，所以容易慢或錯誤。

PDF 要放網站上

PDF 不應只留在本機。比較合理的方式是：

本機或背景流程先產生 PDF
→ 上傳到 Supabase Storage 或靜態檔案空間
→ 網站顯示 PDF 開啟連結

這樣網站能展示 PDF，但不需要每次查詢都在 Render 即時產生 PDF。

Agent 仍是亮點

不能把網站改成單純查資料。正確定位是：

Agent 是分析引擎，網站是展示入口。
  • Agent 負責資料抓取、財務分析、DCF、圖表與報告產出。
  • 網站快速展示 Agent 產出的分析結果。
  • 重任務用快取或背景流程處理。
  • 需要時才按「重新執行 Agent 分析」。

最終建議架構

Render Standard 2GB：
網站、API、PDF 連結、Agent 狀態展示

Supabase：
股票分析結果、PDF URL、產業關聯資料、回測結果

本機 / 背景流程：
抓資料、跑 Agent、產 PDF、更新快取

前端：
產業關聯圖、同業比較、互動式視覺化
