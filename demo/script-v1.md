- 狀態：**Draft／待 A 確認操作畫面、D 核對 trace、組長驗收**
- 適用：fintech-agent 中期展示；本稿是示範腳本，**不是實際執行或驗收紀錄**。
- 依據：`docs/handbook_V1.2/07_論文簡報與最終展示.html`、`docs/handbook_V1.2/個人_E_十四週工作包.html`。
- 展示原則：現場操作必須按實際狀態標明 **LIVE / REPLAY / MOCK / FIXTURE**。人工植入的衝突標為「測試案例」，不得當成真實新聞或正式實驗結果。

## 00:00–00:30｜研究工作台、研究問題與資料截止時間

**畫面操作**：開啟研究工作台，指明畫面是 LIVE 還是 REPLAY；選擇 2330 台積電及已核准的固定研究問題；指出資料截止時間（cutoff）。若使用 MOCK 畫面，須在畫面和口頭說明。

**口說講稿**：
「首先是我們的研究工作台。這裡可以選擇研究標的，今天以 2330 台積電作為操作示範。我們會先確認研究問題，以及這次研究採用的資料截止時間，避免把截止時間之後才出現的資訊混進分析。畫面目前的執行模式也會明確標示，讓大家分辨現場執行與回放內容。」

**核對／替代**：待 A 確認目前網站中 2330、固定研究問題及 cutoff 的實際位置。若畫面是 MOCK，改說「此為 MOCK 驗收展示」，不要稱為 LIVE。

## 00:30–01:20｜研究執行、工具來源與預算狀態

**畫面操作**：在 A 確認可操作的情況下，提交研究工作或開啟已開始的 LIVE job；展示工具選擇、來源回傳、預算／配額計數。若未能現場執行，改用有明確日期與版本的已保存紀錄，並標記 REPLAY。

**口說講稿**：
「研究開始後，Researcher 會依照問題選用所需工具，並保留工具回傳的來源與紀錄。我們不只看最後產出的文字，也會查看資料從哪裡來，以及執行過程中的預算和限制。如果現場遇到排隊或限流，我們會直接展示真實狀態，不會把預錄內容說成即時運算。」

**核對／替代**：待 A 確認可用 LIVE job、工具紀錄及預算計數畫面；組長確認實際限制。不可承諾固定完成秒數，也不可把計畫配額當實測值。

## 01:20–02:10｜衝突測試案例：Reviewer 退件與 Researcher 補查

**畫面操作**：開啟已保存、經 D 核對的「衝突測試」trace；在畫面顯示 **REPLAY／測試案例**。指出 Reviewer 對期間、單位或來源提出核對要求，以及 Researcher 後續補查、修正的紀錄；若 trace 不完整，只展示實際存在的步驟。

**口說講稿**：
「接下來這段是**衝突測試案例的回放，不是現場即時研究**。當證據的期間、單位或來源需要再核對時，Reviewer 可以要求補查，讓 Researcher 回到證據資料進行確認。這段主要展示的是覆核與修正流程，而不是宣稱每個案例都已成功通過。實際結果仍以這份 trace 記錄為準。」

**核對／替代**：待 D 提供或核准衝突 trace 的識別碼、狀態及畫面。不能直接將 CASE-22 等其他案例替代為「已成功補查」；若實際為 `insufficient_evidence`，須如實說明。

## 02:10–02:40｜人工核准報告、來源與線上 PDF

**畫面操作**：開啟經人工核准的研究報告；指出報告版本、資料截止時間及來源連結；由網站操作 PDF 預覽或下載，核對 PDF 與網頁的版本。若使用 A 提供的本機 MOCK 驗收截圖，應清楚標明「本機／MOCK」，不可稱為 Render LIVE。

**口說講稿**：
「完成覆核並經人工核准後，報告才進入發布展示。我們可以在網頁查看報告版本、資料時間和來源，再開啟對應的 PDF。這樣做的重點，是讓閱讀者能追溯同一份報告所依據的版本，而不只是看到一份沒有出處的分析文字。若目前展示的是 MOCK 驗收版本，也會在畫面上直接標明。」

**核對／替代**：A 的 `design/w07/c-figures/README.md` 說明：2026-11-02 截圖為本機 `web_app.py`、MOCK 驗收版本，不是 Render 線上站；其中 2454 範例版本為 `rv-a520d5cc`。這些截圖**不能單獨證明現場 2330 LIVE PDF 已可操作**。待 A 確認本段可展示的線上 PDF、版本日期與手機畫面。

## 02:40–03:00｜資料不足案例與結語

**畫面操作**：開啟 D 核對過的資料不足案例（LIVE 歷史紀錄或明示 REPLAY），指出缺乏關鍵證據時的狀態與不下結論的原因。

**口說講稿**：
「最後是資料不足的情境。當關鍵證據不足時，系統應該保留不足的原因，而不是自行補出結論。**本系統的價值是可查證、可停止與可量測，不是保證預測股價。**」

**核對／替代**：待 D 確認實際不足案例及對應狀態；若未取得，保留此段為待展示，不可使用自行編造的畫面。

## 現場備援說法（依組長展示規格）

- **API 配額不足**：如實顯示 `paused_quota`（僅在實際畫面有此狀態時使用），切換到明示 REPLAY 的已保存紀錄。
- **網站或網路異常**：使用已保存的螢幕錄影，先報出錄製日期、環境與版本，不能稱為現場執行。
- **PDF 無法現場下載**：展示已核對版本的保存檔，明示為備援檔，不聲稱已完成即時下載。
