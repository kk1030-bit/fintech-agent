## 三、異常與處理

1. **執行紀錄公開（11/16）**：排程原本每天把 `runs-v2.jsonl` 推上 GitHub。這份紀錄和盲評答卷對照，可以推出部分答卷是哪個模式。11/17 起改為不推。第 1 天那一列已經公開（commit 21d3a65），請 B、D 交出評分前不要打開（決策 44）。
2. **凍結檔被改（11/17）**：組長合併的 PR #49 改了凍結的評分規則檔，19:30 開跑前嚴格核對沒有通過，runner 依設計停止，當時 0 run。還原凍結版本、修改內容另存後，當晚在同一個配額日手動補跑 6 run（決策 45）。之後 `AGENTS.md` 新增第六節，列出實驗期間不能改的檔案。
3. **輸出截斷檢查（11/17）**：只讀前 12 run 每次發送的結束原因與輸出長度，不讀內容。3 個 run 的最後草稿格式無效：2 個是輸出達到上限被截斷，1 個不是合格 JSON（決策 45）。分析時「格式失敗」和「判定證據不足」分開算，分類規則在 11/25 匯出前定稿。
4. **供應商錯誤（11/19）**：1 個 run 執行到一半時 Gemini 回 `503 UNAVAILABLE`。程式依設計重試一次仍失敗，記為 failed，沒有草稿。原先照決策 46 不重跑；11/21 組長改為供應商錯誤的 run 重跑一次（決策 47），這個 run 於 11/26 重跑，原紀錄保留。
5. **電腦沒開機（11/20）**：19:30 排程時間電腦沒開。開機後排程在 19:51 自動開始，6 run 在同一個配額日跑完。組長端沒有另外手動執行，避免同時跑兩份。

## 四、重跑申請

- 第一批沒有重跑任何 run，也沒有重跑申請。
- 第 2 天的手動補跑是「當天還沒跑的 6 個」，不是重跑：開跑前就被嚴格核對擋下，沒有任何 run 留下紀錄。
- 第 4 天失敗的 run：原決定不重跑（決策 46），11/21 改為 11/26 重跑一次（決策 47）。重跑另寫一列（run_id 加 `-r1`），原紀錄保留。
