------------------------------------------------------------
一、這份規則用來做什麼
評分的人（B與D）看每份輸出時，要用同一套標準判斷：每個關鍵主張有沒有被證據支持、有沒有嚴重錯誤。這份規則就是那套標準。

------------------------------------------------------------
二、每個「關鍵可驗證主張」只能標成以下三種之一

supported（有支持）
意思：有來源，而且來源原文或工具輸出真的支持這個主張，能對到同一版本的快照。
重要：只是附了一個網址不算支持，必須原文支持對應的那個主張。[手冊]

unsupported（不被支持）
意思：有引用或有數字，但原文不支持，或和來源衝突，或用錯口徑（例如幣別混用、單季當成TTM、季營收當全年營收）。[D初稿]

unknown（無法判斷）
意思：目前的證據不足以判斷。例如來源讀不到、缺關鍵欄位、發布時間不明、證據在cutoff之後才出現。[D初稿]
注意：unknown 不能當成 supported，也不能直接當成 unsupported。

名稱容易搞混的地方：
unknown 是評分者對「單一個主張」做的標註。
insufficient 是 Reviewer 對「整份報告」給的決定（decision 只有 pass、revise、insufficient 三種）。[手冊]
兩者不是同一件事。

------------------------------------------------------------
三、critical（重大問題）標註

意思：如果不修正，會讓報告的核心數字或結論出錯的問題。
規則：
1. 每一個 critical 問題都要指到具體的 claim_id。[手冊]
2. Reviewer 的 issues 每一項都要有 claim_id、severity、reason、required_evidence 四個欄位。[手冊]
3. 不能因為文字通順、或估值結果看起來正面，就判定通過。[手冊]
4. 公開報告不能留有未解決的 critical 問題，否則只顯示研究不足或未發布。[手冊 E05]

可以列為 critical 的檢查項目（來自手冊對 Reviewer 的檢查清單）：[手冊]
1. 季度與累計（YTD）混用
2. TTM 與單季混用
3. 實際股價與 EPS、每股淨值（BVPS）不一致
4. CapEx 正負號錯誤
5. 股數、淨負債不一致
6. WACC 不大於 g，卻仍算出 DCF
7. 財報期與可得時間（available_at）搞混
8. 把 2330 當成 2454 的同業平均，而不是產業參照
9. 來源之間互相衝突且未解決

哪些項目一定算 critical、哪些只是次要問題，手冊沒有逐項寫明。上面九項是否全部算 critical，待B確認。[D初稿]
severity 等級的名稱（除了 critical 之外還有哪些），手冊也沒有寫明，待B確認。

和另一個名詞的區別：
網站儀表板上有「資料品質風險」欄位，分高、中、低。那是給網站訪客看的欄位，和這裡的 critical 是兩套不同的東西，不要混用。[手冊 F03]

------------------------------------------------------------
四、分數怎麼算（每個指標都要有分子、分母、NA 數）[手冊]

1. 證據支持率：標成 supported 的關鍵主張數 / 所有關鍵可驗證主張數。沒有任何主張時回報 NA。另外要單獨報拒答率，不能用全部拒答來換 100%。
2. 引用可解析率：能定位到正確快照且可讀的引用數 / 全部引用數。這個和「引用有沒有支持主張」要分開算。
3. 植入錯誤檢出率：被指出的預先植入 critical 錯誤數 / 預先植入的 critical 錯誤總數。沒有植入錯誤的案例另外報誤報率。
4. 修正率：給了修正機會之後，同一個 critical 錯誤不再出現的數量 / 需要修正的數量。只改寫措辭不算修正。
5. 合理拒答率：資料不足的案例中，系統選擇 insufficient 並說明缺口的比例。資料完整卻拒答的情況要另外列。
6. 作業成功率：正常環境中，產出有效格式與正確狀態的 job 比例。429、timeout、failed 都要留在總表裡。
7. 成本與效能：每個 job 的模型發送數、token 用量、工具數、執行時間等。每列都要附實際樣本數 N。沒有帳單時不能填 0 美元。

------------------------------------------------------------
五、評分流程 [手冊]
1. B 和 D 各自對匿名化、且打亂模式標籤的輸出評分。
2. 先各自獨立評分，不看對方的分數。
3. 兩人有差異時，由組長裁決，原始分數兩份都要保留。
4. C 和 E 只負責整理表格，不負責標準答案，也不判斷模型準確率。

------------------------------------------------------------
六、禁止事項 [手冊]
1. 不能只看文字流暢度打分。
2. 不能把「模擬（mock）」當成「實測（live）」。
3. 不能用保留案例（20個）的答案去調整 prompt。
4. 失敗的 run 不能刪，要保留在總表。
5. 缺值保留 null 與原因，不能補數字，也不能把缺值當成 0。
6. 不預設雙 Agent 一定比較好，負結果也要照實保留。

------------------------------------------------------------
七、待確認事項（交給B或組長）
1. unsupported 和 unknown 的界線，是否同意本檔的寫法。
2. critical 九項檢查項目是否全部算 critical。
3. severity 除 critical 外的等級名稱。
4. 單一主張如果同時有支持與不支持的部分，怎麼標。
